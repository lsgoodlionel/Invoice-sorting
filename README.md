# 发票账本 · 个人发票报销管理工具

把“收发票、找截图、凑凭证、记进度、打包外送”变成 **拖进来 → 点一下 → 打个包**。

面向个人使用的发票与报销过程管理工具：集中存放发票和凭证，记录每笔支出从“已支出”到“已报销”的全过程，提醒还缺哪些材料，并按批次输出分类整理好的报销资料包。可以在自己电脑上运行，也可以一键部署到 Ubuntu 服务器上通过浏览器访问。

- 设计文档：[开发蓝图 v2.0](docs/个人发票报销管理工具_开发蓝图_v2.0.md) · [凭证识别与自动归并 v2.1](docs/凭证识别与自动归并_设计_v2.1.md)
- 接口说明：[API 契约](docs/api-contract.md)

## 功能概览

| 模块 | 能做什么 |
| --- | --- |
| **收集** | 发票、订单截图、银行交易截图、收据、行程单一起拖进来；识别发票内容，用本地 OCR 识别截图；**同一笔支出的多个文件自动归为一组**，并判断是挂到已有记录还是新建；重复凭证自动拦截；也可以放进“收件箱”文件夹自动导入 |
| **境外无发票** | Claude、ChatGPT、Windsurf 等境外订阅只有订单/收据和银行交易，也能作为“免发票”记录报销：人民币金额取银行入账，保留原币（如 US$20.00） |
| **补传凭证** | 清单页把文件直接拖到某一行即上传到该记录；或在收集页上传，系统按订单号、文件名、金额日期自动找到对应记录 |
| **清单** | 所有支出一张表，按状态分组显示数量与金额；按周期、日期口径、分类、经费项目、关键词筛选；显示每条记录缺几项凭证；详情抽屉里补传凭证、改分类、看时间线 |
| **凭证清单** | 按分类与金额自动列出需要的材料（如≥1000 元需支付记录、易耗品需验收单），缺什么一目了然；不需要的可标记“不需要”并写原因 |
| **状态跟踪** | 已支出 → 已开票 → 凭证齐全 → 已外发 → 已报销，按材料和批次自动推进，也可手动设置；每次变化记入时间线 |
| **批次** | 把要一起报销的记录组成批次，一键生成资料包 ZIP（汇总 Excel + 合并打印 PDF + 发票原件 + 分类支撑材料）；登记外发、到账（支持部分到账）；可重新打开 |
| **统计** | 按月 / 季度 / 年 / 自定义区间，按分类、经费项目、商家、月份交叉汇总；可切换支出、开票、外发、到账日期口径；点数字直达明细；导出 Excel |
| **开票地区** | 按发票号码识别开票地区；外地发票自动要求订单截图（京东、当当、圆迈等已带明细平台可免） |
| **提醒** | 顶部提醒条：凭证缺项、外发超期未到账、已支出久未开票、待归属附件 |
| **归档** | 文件自动按 `年/月/日期_商家_分类_金额` 整理，不打开应用也能直接浏览 |

支持识别：

- **发票**：数电发票（全电）PDF / XML（含京东、圆迈等电商开具的版式）、增值税电子普通/专用发票 PDF、OFD 版式发票、铁路电子客票、航空运输电子客票行程单
- **截图与其他凭证**（本地 OCR，离线运行）：京东/淘宝/拼多多交易订单、App Store 订阅订单、境外收据与账单（Stripe 类）、银行卡交易明细、微信/支付宝账单、打车电子行程单

无法识别的文件会作为附件导入，手工填写即可。

## 快速开始（本机）

需要：[uv](https://docs.astral.sh/uv/)（自动安装 Python 3.12）、Node.js ≥ 20 与 pnpm（构建前端）。

```bash
git clone https://github.com/lsgoodlionel/Invoice-sorting.git
cd Invoice-sorting
bash scripts/setup.sh
backend/.venv/bin/invoice-sorting
```

`scripts/setup.sh` 会安装后端依赖（含 OCR）、安装前端依赖并构建。安装前它会**实测官方源与国内镜像（阿里云、清华、npmmirror）的下载速度，自动选最快的源**，并严格按锁文件版本安装：

| 变量 | 说明 |
| --- | --- |
| `MIRROR=auto` | 默认，测速自动选择 |
| `MIRROR=cn` | 强制国内镜像 |
| `MIRROR=global` | 强制官方源 |
| `NO_OCR=1` | 不安装 OCR（约 200MB；截图只按文件名识别，可之后[单独安装](#单独安装-ocr截图识别)） |
| `PYPI_INDEX` / `NPM_REGISTRY` | 手工指定源地址，跳过测速 |

启动后自动打开 <http://127.0.0.1:8765>。本机模式只监听 127.0.0.1，不对局域网开放。

更新到最新版本：

```bash
git pull && bash scripts/setup.sh && backend/.venv/bin/invoice-sorting
```

### 单独安装 OCR（截图识别）

截图、图片类凭证（交易订单、银行交易、收据等）的文字识别依赖 `rapidocr`、`onnxruntime`、`opencv-python`，下载量约 200MB。安装时用 `NO_OCR=1` 跳过、或下载太慢中断时，可以之后单独补装。以下命令**按锁文件版本安装**（带哈希校验），已安装的包会自动跳过。

**本机**（在仓库根目录执行）：

官方源：

```bash
cd backend && uv export --quiet --frozen --no-dev --no-emit-project --extra ocr --format requirements-txt -o /tmp/ocr-req.txt && uv pip install --python .venv/bin/python --index-url https://pypi.org/simple -r /tmp/ocr-req.txt
```

阿里云镜像：

```bash
cd backend && uv export --quiet --frozen --no-dev --no-emit-project --extra ocr --format requirements-txt -o /tmp/ocr-req.txt && uv pip install --python .venv/bin/python --index-url https://mirrors.aliyun.com/pypi/simple -r /tmp/ocr-req.txt
```

装好后重启应用即可生效。

**Ubuntu 服务器**（一键部署安装的实例）：

> 前提：一键安装已经成功完成（终端最后打印了“发票账本已就绪”）。可用下面的命令确认后端运行环境存在，输出 `环境正常` 才继续；若提示不存在，请先重新执行一键安装命令（可加 `NO_OCR=1` 先快速装好）：
>
> ```bash
> test -x /opt/invoice-sorting/app/backend/.venv/bin/python && echo 环境正常 || echo 后端环境不存在，请先完成一键安装
> ```

1. 安装 OCR 运行所需的系统库：

   ```bash
   sudo apt-get install -y libgl1 libglib2.0-0
   ```

2. 以程序用户 `invoice` 安装依赖（二选一）。

   官方源：

   ```bash
   cd /opt/invoice-sorting/app/backend && sudo -u invoice env HOME=/opt/invoice-sorting UV_NO_CONFIG=1 UV_HTTP_TIMEOUT=300 UV_CACHE_DIR=/opt/invoice-sorting/.cache/uv sh -c 'uv export --quiet --frozen --no-dev --no-emit-project --extra ocr --format requirements-txt -o /opt/invoice-sorting/.cache/ocr-req.txt && uv pip install --python .venv/bin/python --index-url https://pypi.org/simple -r /opt/invoice-sorting/.cache/ocr-req.txt'
   ```

   阿里云镜像：

   ```bash
   cd /opt/invoice-sorting/app/backend && sudo -u invoice env HOME=/opt/invoice-sorting UV_NO_CONFIG=1 UV_HTTP_TIMEOUT=300 UV_CACHE_DIR=/opt/invoice-sorting/.cache/uv sh -c 'uv export --quiet --frozen --no-dev --no-emit-project --extra ocr --format requirements-txt -o /opt/invoice-sorting/.cache/ocr-req.txt && uv pip install --python .venv/bin/python --index-url https://mirrors.aliyun.com/pypi/simple -r /opt/invoice-sorting/.cache/ocr-req.txt'
   ```

3. 预先下载识别模型（约 30MB，首次识别时也会自动下载）并确认可用，然后重启服务：

   ```bash
   cd /opt/invoice-sorting && sudo -u invoice /opt/invoice-sorting/app/backend/.venv/bin/python -c "from rapidocr import RapidOCR; RapidOCR(); from invoice_sorting.evidence import ocr_available; print('OCR 可用:', ocr_available())"
   ```

   ```bash
   sudo systemctl restart invoice-sorting
   ```

> 之后再执行一键安装/升级命令时，若没有带 `NO_OCR=1`，脚本会自动保持 OCR 依赖为锁文件版本。

可用环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `INVOICE_SORTING_DATA_DIR` | `~/InvoiceSorting` | 数据目录 |
| `INVOICE_SORTING_HOST` | `127.0.0.1` | 监听地址 |
| `INVOICE_SORTING_PORT` | `8765` | 端口 |
| `INVOICE_SORTING_OPEN_BROWSER` | `true` | 启动时是否打开浏览器 |
| `INVOICE_SORTING_WATCH_INBOX` | `true` | 是否监听收件箱文件夹 |
| `INVOICE_SORTING_FRONTEND_DIST` | `frontend/dist` | 前端构建目录 |
| `INVOICE_SORTING_AUTH_ENABLED` | `true` | 登录认证；仅本机单人使用时可设为 `false` 关闭 |

## 部署到 Ubuntu 服务器

适用于 Ubuntu 22.04 / 24.04（x86_64 或 arm64）。**安装与升级是同一条命令**，重复执行即升级，数据和登录密码会保留，升级前自动备份数据库。

### 一键安装 / 升级

```bash
curl -fsSL https://raw.githubusercontent.com/lsgoodlionel/Invoice-sorting/main/deploy/install.sh | sudo bash
```

完成后通过 `http://服务器IP:8765` 访问（云服务器需在安全组放行 8765 端口）。**首次打开网页会要求为管理员账户 `admin` 设置初始密码**，设置前无法使用任何功能；之后可在「设置 → 用户管理」添加其他用户。安装完成后请尽快打开页面完成设置（设置前任何能访问该地址的人都可以设置）。

### 使用域名并启用 HTTPS

域名需已解析到服务器，且 80/443 端口可访问（Let's Encrypt 证书验证需要 80 端口，因此启用 HTTPS 时使用标准 80/443 端口）：

```bash
curl -fsSL https://raw.githubusercontent.com/lsgoodlionel/Invoice-sorting/main/deploy/install.sh | sudo DOMAIN=invoice.example.com ENABLE_HTTPS=true EMAIL=you@example.com bash
```

### 忘记登录密码

普通用户忘记密码由管理员在「设置 → 用户管理」中重置。管理员 admin 忘记密码时，在服务器上执行以下命令清除 admin 密码，然后重新打开网页为 admin 设置新的初始密码（admin 已登录的设备会全部退出）：

```bash
sudo -u invoice env INVOICE_SORTING_DATA_DIR=/var/lib/invoice-sorting /opt/invoice-sorting/app/backend/.venv/bin/invoice-sorting reset-password
```

### 部署选项

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DOMAIN` | `_`（任意域名 / IP） | Nginx `server_name` |
| `ENABLE_HTTPS` | `false` | `true` 时通过 Let's Encrypt 申请证书并强制跳转 HTTPS（需 `DOMAIN`、`EMAIL`） |
| `EMAIL` | — | 证书通知邮箱 |
| `HTTP_PORT` | `8765`（启用 HTTPS 时 `80`） | 对外访问端口（Nginx） |
| `APP_PORT` | `18765` | 应用内部端口（仅本机，不对外） |
| `BRANCH` | `main` | 部署的 Git 分支 |
| `INSTALL_DIR` | `/opt/invoice-sorting` | 程序目录 |
| `DATA_DIR` | `/var/lib/invoice-sorting` | 数据目录 |
| `MIRROR` | `auto` | 下载源：`auto` 测速选择 / `cn` 国内镜像 / `global` 官方源 |
| `NO_OCR` | `0` | 设为 `1` 不安装截图识别（之后可[单独安装](#单独安装-ocr截图识别)） |
| `FRONTEND_BUILD` | `prebuilt` | `prebuilt`：下载 GitHub Actions 预构建的前端（服务器无需 Node.js），失败时自动改为本地构建；`local`：始终在服务器上构建 |

### 脚本做了什么

1. 安装 git、Nginx、sqlite3 及 OCR 所需系统库；测速选择下载源后，从选中的源安装 uv
2. 创建无登录权限的系统用户 `invoice`
3. 若已有数据库，升级前备份到 `数据目录/备份/upgrade_时间.db`（保留最近 10 份）
4. 拉取代码（已安装则更新到最新提交），安装后端依赖；前端直接下载 CI 预构建版本（约 300KB，校验与代码版本一致），下载失败或版本不一致时才安装 Node.js 22 在服务器上构建
5. 注册 systemd 服务 `invoice-sorting`（开机自启、异常自动重启，仅监听 127.0.0.1:18765）
6. 配置 Nginx 反向代理（对外 8765 端口），上传上限 100 MB；登录由应用自身负责（首次打开网页设置初始密码）
7. 防火墙 ufw 已启用时放行端口；按需申请 HTTPS 证书
8. 健康检查通过后打印访问信息

> 公网部署建议启用 HTTPS，避免登录密码与会话在网络中明文传输。

### 运维命令

```bash
sudo systemctl status invoice-sorting      # 运行状态
sudo journalctl -u invoice-sorting -f      # 实时日志
sudo systemctl restart invoice-sorting     # 重启
```

服务器上的收件箱位于 `/var/lib/invoice-sorting/收件箱/`，可以用 `scp`/`rsync` 把发票批量传进去自动导入：

```bash
scp *.pdf user@server:/tmp/ && ssh user@server 'sudo install -o invoice -g invoice -m 640 /tmp/*.pdf /var/lib/invoice-sorting/收件箱/'
```

## 使用指南

### 典型流程

```text
付款后（可选）  清单页按 N「记一笔」：日期、金额、商家 → 状态「已支出」
收到凭证       收集页把发票、订单截图、支付记录一起拖入 → 自动归组、匹配已有记录 →「全部确认」
补齐凭证       把补充材料拖到清单对应行，或再次拖进收集页自动关联 → 状态自动变「凭证齐全」
准备报销       批次页新建批次 →「添加记录」→「生成资料包」→ 把 ZIP 交给财务/经办人
外发后         「标记已外发」填日期、接收人、预约单号 → 状态「已外发」
钱到账后       「登记到账」（可只勾选部分记录）→ 状态「已报销」
```

### 收集：导入发票与凭证

- **拖放导入**：把发票（PDF / XML / OFD）、截图（PNG / JPG / WEBP / HEIC）、行程单等一次性拖进虚线框，或点击选择文件。
- **自动归为凭证组**：属于同一笔支出的文件自动归为一组，依据按可靠程度依次为：
  1. **订单号一致**：发票备注的“订单号”与交易订单截图的“订单编号”相同
  2. **文件名一致**：去掉“发票/订单/银行交易/收据/账单/行程单”、金额、地区后剩余部分相同，如 `办公-20260312-升降桌-459-江苏.pdf` 与 `办公-20260312-升降桌-交易订单.PNG`
  3. **金额与日期一致**：不同类型凭证金额相同、日期相差 3 天内且商家相近
  4. **境外订单与银行交易**：外币订单/收据与境外银行交易日期相近，卡号末四位一致更可靠

  每组最多一张发票；订单号不同的两套凭证不会混在一起。
- **判断是否首次上传**：每组都会去找已有记录。订单号或文件名对得上的直接建议“挂到 #id”；否则按金额、日期、商家、该记录是否正好缺这类凭证打分，分数够高且明显领先才建议挂上，其余列为候选；都没有则建议新建。同一订单的同类凭证已上传过，会提示“可能重复”并默认跳过。
- **导入确认表（按组）**：每组显示文件卡片、关联依据、识别出的日期、商家、人民币金额与原币、分类、网购、免发票，均可修改。
  - 文件卡片可改类型、“移到其他组”、“拆为单独一组”。
  - “操作”可选新建记录、挂到建议或候选记录、搜索其他记录、留在待归属。
  - 黄色提示需要留意，例如购方不一致、外地发票需订单、可能重复。
  - 核对无误后点 **全部确认**。
- **重复拦截**：同一文件、同一发票号码再次导入直接跳过。
- **收件箱自动导入**：把文件放进数据目录下的 `收件箱/`，几秒后自动按组处理：强匹配的挂上去，金额和日期齐全的新建，其余留在待归属；无法处理的移到 `收件箱/无法处理/` 并附说明。

### 待归属：怎么处理、怎么重新归属

待归属是**已导入但还没挂到任何记录**的文件，例如确认时选了“留在待归属”、识别不出内容、或只有截图还找不到对应记录。收集页下方的待归属列表：

- 每个文件显示识别结果和**建议记录**（如“建议挂到 #12 京东 ¥459（订单号一致）”），点 **采纳** 即归属。
- 勾选多个后批量操作：
  - **生成记录**：按凭证组规则自动新建或挂上
  - **归属到记录…**：手工选择记录，可同时设类型
  - **重新识别**：识别规则更新后重新解析
  - **删除**：文件移入回收站
- 已归属的文件想换记录：在记录详情的附件列表里“移回待归属”，再重新归属。

**分类是怎么自动识别的？** 按以下顺序：

1. **商品记忆**：你曾把某个商品（如“收纳盒”）改成某分类，下次同名商品直接用该分类
2. **商家记忆**：该销售方上次使用的分类
3. **发票税收分类简称**：如 `*日用杂品*` → 办公用品、`*计算机配套产品*` → 易耗品
4. **关键词**：商品名称、销售方名称中包含的关键词，取最长命中者（“打印纸”优先于“打印机”）
5. 凭证文件名首段分类词（如 `办公-…`、`软件-…`、`图书-…`）也会参与建议
6. 都不命中归为“其他”

识别不准时，在导入确认表或详情里改一次分类，系统就会记住。关键词可以在「设置 → 分类」里增删。

### 清单：跟进每笔支出

- **筛选**：周期（本月 / 本季度 / 本年 / 上月 / 上季度 / 全部 / 自定义）、日期口径、分类、经费项目、搜索（商家 / 摘要 / 发票号）。筛选条件保存在网址里，可收藏。
- **状态条**：6 个状态的数量与金额，点击即按该状态筛选。
- **表格**：日期、商家·摘要、分类、金额、状态、「缺 N 项」徽标、所属批次。
- **详情抽屉**（点击任一行）：
  - 状态步进条：点击某一步手动设置状态，手动状态显示“手动”标记，可“恢复自动”
  - 基本信息：日期、金额、商家、摘要、分类、**经费项目**（下拉底部可直接新建）、付款方式、网购、备注，离开输入框自动保存
  - 凭证清单：每项显示是否已有、提示说明；缺项行内直接拖入文件上传；「不需要」可填原因，「恢复」撤销
  - 办理路径：该分类的平台操作路径与填报科目，一键复制
  - 附件：预览 PDF / 图片、修改材料类型、移回待归属、删除
  - 时间线：每次状态变化的时间、自动/手动与备注
  - 危险操作：作废（需填原因）、删除（文件移入回收站）
- **批量操作**：勾选多条后按 `B` 或点「加入批次」。
- **快捷键**：`N` 记一笔，`/` 搜索，`B` 加入批次，`Esc` 关闭抽屉。

### 补传凭证的两种方式

一笔支出的凭证经常分几次拿到：先有发票后补支付截图，先有订单后补银行交易，或反过来。

1. **拖到清单行**：清单页找到这条记录，把文件直接拖到这一行上（或打开详情，拖到凭证清单的缺项行），系统自动识别是订单、支付记录还是行程单并归档，凭证清单与状态随即更新。
2. **在收集页上传**：不用找记录，直接拖进收集页。系统按订单号、文件名、金额日期找到对应记录并建议“挂到 #id”；没找到或找错了，在确认表里改选记录，或留在待归属稍后“采纳建议”/“归属到记录…”。

### 境外订阅（无发票）

境外服务通常只有订单/收据和银行交易记录。把两者一起上传（或先后上传），系统会：

- 归为一组，标记为 **免发票** 记录；人民币金额取银行交易入账金额，原币金额（如 US$20.00）一并保存。
- 凭证清单不再要求发票，改为要求：订单或收据（必需）、银行卡交易明细（必需）、情况说明（建议）。
- 清单中显示“免发票”徽标和原币金额；状态第二步显示为“已收凭证”。

也可以在任何记录详情里手动打开“免发票（境外消费）”开关并设置币种。

### 开票地区与订单凭证

- 数电发票号码第 3–4 位是开票税务机关所在省份（如 `25`**`31`**`7…` 上海、`25`**`11`**`7…` 北京）；旧版发票看发票代码，都没有时看销售方信用代码。
- 与「设置 → 本地地区」（默认上海）不同即为 **外地发票**，自动增加必需凭证“订单明细”（外地发票需附网购订单截图）；销售方属于「已带明细平台」（默认京东、当当、圆迈）时可免。
- 发票上有“订单号”或销售方是电商平台时，自动标记为网购。

### 差旅住宿凭证

一笔住宿差旅报销 = **酒店发票 + 酒店订单 + 往来交通凭证**，可以一次上传，也可以分多次、由不同用户补传：

- **识别**：携程/美团/飞猪/同程/Booking 等酒店订单（PDF 或截图）读出酒店、城市、入住离店日期、晚数、房间数；12306、航司等车票机票订单识别为“往来交通凭证”；铁路电子客票、航空行程单、汽车/船票发票读出出发地、到达地、车次航班。
- **归组**：酒店发票与订单按金额 + 酒店名 + 日期自动归为一组；入住前后 1 天内、往返酒店所在城市的车票机票并入同一组。摘要如“某某酒店 1晚 + 交通 2 张”，金额 = 组内全部发票合计（订单不重复计）。
- **补传**：之后再上传交通票或住宿发票，会自动匹配到已有的住宿记录；交通票发票挂上后，记录金额自动加上票价（时间线记“并入交通票 ¥xx”），手动改过金额的记录不会自动调整。
- **只有订单或只有交通凭证**时照常建记录，清单显示缺发票/缺往来交通凭证，补齐后自动变为凭证齐全。

### 批次：打包外送

- **新建批次**：填写名称（如“2026-09 科研A 第1批”）、可选经费项目。新批次为空时会直接弹出「添加记录」。
- **添加记录**：批次页「添加记录」列出所有未分批、未作废的记录（默认只显示与批次相同经费项目的记录，可切换显示全部），勾选后加入；也可以在清单页勾选后「加入批次」。
  - 弹窗顶部可按日期周期（本月、本季度、近3/5/10年或自选起止日期）与日期口径（支出/开票/外发/到账）、分类、经费项目、状态、缺不缺凭证筛选；显示符合条件的条数与合计，可「全选当前筛选结果」。
- **批次筛选**：左侧批次列表可按状态（待外发/已外发/部分到账/已到账）和日期周期（口径：创建/外发/到账日期）筛选，显示批次数与合计金额，筛选条件保存在地址栏；批次详情的记录表可按分类、状态筛选（打包仍包含整个批次）。
  - 记录仍有必需凭证缺项、或经费项目与批次不一致时会提示原因，确认后可「仍然加入」。
- **生成资料包**：选择分组方式后生成 ZIP，每次生成新文件、保留历史包，可随时重新下载：

  ```text
  报销资料_科研A_20260917_1402.zip
  ├── 00_报销汇总表.xlsx        汇总（序号/日期/商家/摘要/分类/金额/发票号/附件清单/缺项/备注 + 合计）与分类小计
  ├── 01_打印版_全部材料.pdf     按序号合并：发票 → 订单 → 支付记录 → 验收单 …（图片自动排成 A4）
  ├── 02_发票原件/              原始电子发票，未经修改
  │   └── 01_易耗品_960.00_京东××店_26312000000123456789.pdf
  └── 03_支撑材料/              按支出分组：01_京东××店_960.00/订单明细_1.png
                                或按材料类型分组：订单明细/01_京东××店_960.00_1.png
  ```

  序号贯穿汇总表、打印 PDF 和文件名，方便财务对照；发票原件文件名依次为 `序号_分类_金额_商家_发票号`。

  **按支出分组 vs 按材料类型分组**：两者汇总表、打印版 PDF、发票原件完全相同，只有 `03_支撑材料/` 的目录结构不同——
  - 按支出分组：一笔支出的所有材料放在一个文件夹，适合财务逐笔核对、按笔打印装订；
  - 按材料类型分组：订单明细、支付记录、验收单等同类材料各放一个文件夹，适合报销系统要求按附件类型分别上传。
- **删除资料包**：打包历史中每个资料包右侧的删除按钮可删除该 ZIP（二次确认），记录与凭证不受影响，可随时重新生成。
- **标记已外发**：填写外发日期、方式、接收人、外部单号（如预约报销单号），批次内记录变为「已外发」。已外发的批次不能再增删记录。
- **登记到账**：全部或勾选部分记录到账，批次显示「部分到账」/「已到账」。
- **重新打开**：外发或到账登记有误时，重新打开回到待外发状态，记录状态按凭证清单重新计算。

### 统计

- 选择周期和日期口径（支出日期 / 开票日期 / 外发日期 / 到账日期），页面标题会注明“按××日期统计”。
- 四个数字：本期支出（不含作废）、待处理（已支出 + 已开票 + 凭证齐全）、在途（已外发未到账）、已报销（实际到账），作废金额单列。
- 交叉表：按分类 / 经费项目 / 商家 / 月份分组 × 状态，点击金额跳转到对应明细；统计数字与清单页同条件合计保持一致。
- 按月趋势柱状图；「导出 Excel」输出汇总与明细。

### 用户与登录

- **管理员 admin**：系统内置管理员账户。首次打开网页时为 admin 设置初始密码（8–128 个字符，输入两次），设置完成后自动登录；设置前所有数据都无法访问。
- **添加用户**：管理员在「设置 → 用户管理」添加用户（用户名、姓名、角色、初始密码），也可以重置密码、修改姓名与角色、停用/启用用户。停用或重置密码后，该用户所有设备立即退出登录。系统始终保留至少一名启用中的管理员，管理员不能停用自己或取消自己的管理员身份。
- **角色权限**：

  | 功能 | 管理员 | 普通用户 |
  | --- | --- | --- |
  | 收集凭证、补传、处理记录、批次打包、统计 | ✔ | ✔ |
  | 经费项目新建与编辑、修改自己的密码 | ✔ | ✔ |
  | 用户管理 | ✔ | — |
  | 系统设置（购方抬头、本地地区、分类、凭证清单规则、备份） | ✔ | 只读 |

- **多人协作补全凭证**：所有用户共用同一个账本。同一套凭证可以由不同人分别上传，例如 A 上传发票、B 之后上传订单截图或银行交易，系统照样自动归并到同一条记录。每个附件显示上传人（收件箱自动导入的显示“收件箱”），记录显示创建人，时间线显示每次状态变化的操作人，批次与资料包显示创建/生成人。

## 核心概念

### 支出记录与报销批次

- **支出记录**：一次花钱的事，例如“9 月 15 日 京东 鼠标 ×2 960 元”，包含基本信息、附件（发票、订单、支付记录、验收单等）、凭证清单、状态与时间线。
- **报销批次**：一次外送给财务/经办人的资料集合，包含若干支出记录、打包历史、外发与到账信息。

### 状态

| 状态 | 含义 | 自动进入条件 |
| --- | --- | --- |
| 已支出 | 钱花了，发票还没到 | 新建记录且没有发票 |
| 已开票 | 发票已收到并确认（免发票记录显示为“已收凭证”） | 有已确认的发票附件；免发票记录有订单/收据或支付记录 |
| 凭证齐全 | 需要的材料都有了 | 凭证清单必需项全部“已有”或“不需要” |
| 已外发 | 已交给财务/经办人 | 所在批次标记已外发 |
| 已报销 | 钱已到账 | 所在批次登记该记录到账 |
| 不报销/作废 | 个人承担、重复、退货等 | 仅手动设置，需填原因 |

手动设置的状态不会被自动回退；作废或删除记录会自动移出待外发批次，已外发批次中的记录需先重新打开批次。

### 默认分类与凭证清单

| 分类 | 默认必需材料（在通用规则之外） | 办理提示 |
| --- | --- | --- |
| 办公用品 | 网购或≥500 元：订单明细 | 不在设备与实验室平台填报 |
| 易耗品 / 低值品 / 材料 | 订单明细、验收单 | 材料易耗品低值品报账，打印验收单，填“材料费” |
| 设备 | 申购单、验收单、支付记录 | 单价≥1000 元先申购，申购日期早于购买日期 |
| 软件服务 | 订单、软件服务报账单、验收单 | 填“委托其他业务费” |
| 图书 | 购书清单/送货清单；≥500 元（建议）图书馆验收单 | 单册或单套≥500 元图书馆验收；非书店购买附电脑小票 |
| 印刷快递 | （建议）明细 | 票面已开明细可免 |
| 差旅交通 | 交通票：行程单；住宿：酒店订单（显示入住人、入住离店日期、房间数与单价）+ 往来交通凭证（往返酒店所在地的火车/飞机/汽车/轮船票或行程单） | 个人出行与节假日不报 |
| 餐饮会议 | （建议）工作餐单或会议材料 | 工作餐 50 元/人/餐 |
| 其他 | — | — |

通用规则：

- 需发票（免发票记录除外）；金额≥1000 元需支付记录；金额≥30000 元需合同
- 外地发票需订单明细（已带明细平台可免）
- 免发票记录需订单或收据、银行交易明细，建议附情况说明

> 以上规则整理自学校报销要点，**仅作提醒，以学校现行规定为准**，可在设置中按实际情况修改。

## 常见问题

**经费项目在哪里创建、怎么关联？**
三处都可以：「设置 → 经费项目」集中管理；记录详情的“经费项目”下拉底部「＋ 新建经费项目」；新建批次或批次信息中的项目下拉同样可以新建。记录关联项目后，可在清单和统计中按项目筛选汇总；批次设置项目后，「添加记录」默认只列出该项目的记录。

**发票被分到“其他”怎么办？**
在导入确认表或记录详情里改成正确的分类即可，系统会记住这个商品名称和商家，下次自动归类。也可以在「设置 → 分类」给对应分类添加关键词。

**在哪里标记“已报销”？**
批次页选中批次 →「标记已外发」→ 之后按钮变为「登记到账」，填写到账日期（可只勾选已到账的记录）→ 记录变为“已报销”。未走批次的记录，可在详情顶部状态步进条上直接点“已报销”手动设置。

**同一套凭证分开上传，会不会重复建记录？**
不会。后上传的文件会按订单号、文件名、金额日期匹配到已有记录并建议挂上；同一订单的同类凭证再次上传会提示“可能重复”。如果建议不对，在确认表中改选记录即可。

**截图识别不准或没装 OCR？**
截图识别在本机离线进行（首次使用会自动下载约 30MB 模型）。未安装 OCR（`NO_OCR=1`）时，截图只按文件名判断类型并参与分组，金额等需手工填写。识别不准可在确认表修改，或在待归属中“重新识别”。

**批次打包时找不到已上传的发票？**
发票需要先加入批次：在批次页点「添加记录」勾选，或在清单页勾选记录后「加入批次」。已在其他批次、已作废的记录不会出现在可添加列表中。

**识别出来的金额或日期不对？**
导入确认表中可以直接修改；确认后在记录详情里也能修改。识别不出的发票会作为附件导入，手工填写即可。建议把识别有误的发票版式反馈到 Issues。

**可以多人使用吗？**
可以。管理员 admin 在「设置 → 用户管理」添加用户，大家共用同一个账本，分别上传的凭证会自动归并，并记录上传人与操作人。

**忘记登录密码怎么办？**
普通用户：请管理员在「设置 → 用户管理」重置密码。管理员 admin：在服务器执行 `sudo -u invoice env INVOICE_SORTING_DATA_DIR=/var/lib/invoice-sorting /opt/invoice-sorting/app/backend/.venv/bin/invoice-sorting reset-password`（本机：`backend/.venv/bin/invoice-sorting reset-password`），然后重新打开网页为 admin 设置初始密码。也可以用 `reset-password --user 用户名` 清除指定用户的密码。

**如何迁移到另一台电脑或服务器？**
停止应用后复制整个数据目录到新位置（服务器上注意 `chown -R invoice:invoice /var/lib/invoice-sorting`），再启动即可。
