# 发票账本 · 发票报销管理工具

把「收发票、找截图、凑凭证、记进度、打包外送」变成 **拖进来 → 点一下 → 打个包**。

发票和凭证集中存放，每笔支出从「已支出」走到「已报销」的过程自动跟着走，还缺哪些材料一眼看得见，
要报销时一键生成分类整理好的资料包。可以在自己电脑上跑，也可以装到服务器上让一个团队甚至多家客户共用。

设计与运维文档：[部署与运维](docs/部署与运维.md) · [多租户与私有化](docs/多租户与私有化_设计.md) · [日志与故障上报](docs/日志与故障上报_设计.md) ·

## 选哪种形态

同一套代码、同一条安装命令，靠环境变量区分三种用法。**不确定就选单账套**，以后可以用
[账套搬迁](docs/部署与运维.md#八账套搬迁)把数据搬到 SaaS，反过来也行。

| 形态 | 适合谁 | 怎么装 |
| --- | --- | --- |
| **本机自用** | 一个人在自己电脑上用 | [快速开始（本机）](#快速开始本机) |
| **私有化单账套**（默认） | 一个团队或一家客户独占一套服务 | 一键安装命令，不加任何变量 |
| **SaaS 多账套** | 一套服务承载多个客户，每家一个独立账套 | 一键安装命令加 `DEPLOY_MODE=saas` |

单账套模式下界面里**完全不出现「账套」概念**，老部署升级后行为不变、数据文件也不搬家。

## 功能概览

| 模块 | 能做什么 |
| --- | --- |
| **收集** | 发票、订单截图、银行交易截图、收据、行程单一起拖进来；识别发票内容，用本地 OCR 识别截图；**同一笔支出的多个文件自动归为一组**，并判断是挂到已有记录还是新建；重复凭证自动拦截；也可以放进「收件箱」文件夹自动导入 |
| **补传凭证** | 凭证分几次才拿齐是常态：把文件拖到清单里的某一行即挂到该记录；或直接拖进收集页，系统按订单号、文件名、金额日期找到对应记录。不同用户分别上传也能归到一起 |
| **境外无发票** | Claude、ChatGPT 等境外订阅只有订单/收据和银行交易，也能作为「免发票」记录报销：人民币金额取银行入账，保留原币（如 US$20.00） |
| **差旅住宿** | 酒店发票 + 酒店订单 + 往来交通凭证自动归为一组，交通票金额并入同一笔差旅；缺哪一样都会提示 |
| **清单** | 所有支出一张表，按状态分组显示数量与金额；按周期、日期口径、分类、经费项目、关键词筛选；显示每条记录缺几项凭证；详情抽屉里补传凭证、改分类、看时间线 |
| **凭证清单与状态** | 按分类与金额自动列出需要的材料（如 ≥1000 元需支付记录、易耗品需验收单），缺什么一目了然；已支出 → 已开票 → 凭证齐全 → 已外发 → 已报销随材料与批次自动推进，也可手动设置 |
| **批次** | 把要一起报销的记录组成批次，一键生成资料包 ZIP（汇总 Excel + 合并打印 PDF + 发票原件 + 分类支撑材料）；登记外发、到账（支持部分到账）；可重新打开 |
| **统计** | 按月 / 季度 / 年 / 自定义区间，按分类、经费项目、商家、月份交叉汇总；可切换支出、开票、外发、到账日期口径；点数字直达明细；导出 Excel |
| **开票地区** | 按发票号码识别开票地区；外地发票自动要求订单截图（京东、当当、圆迈等已带明细平台可免） |
| **多人协作** | 管理员添加用户，大家共用同一个账本；记录上传人、操作人、批次与资料包的经手人 |
| **提醒与归档** | 顶部提醒条汇总凭证缺项、外发超期未到账、久未开票、待归属附件、授权与额度状态；文件自动按 `年/月/日期_商家_分类_金额` 整理，不打开应用也能浏览 |

**能识别的发票**：数电发票（全电）PDF / XML（含京东、圆迈等电商开具的版式）、增值税电子普通/专用发票 PDF、
OFD 版式发票、铁路电子客票、航空运输电子客票行程单。**截图与其他凭证**（本地 OCR，离线运行）：
京东/淘宝/拼多多交易订单、App Store 订阅订单、境外收据与账单（Stripe 类）、银行卡交易明细、微信/支付宝账单、
打车电子行程单、携程/美团/飞猪等酒店订单、12306 与航司的车票机票订单。无法识别的文件会作为附件导入，手工填写即可。

## 快速开始（本机）

需要 [uv](https://docs.astral.sh/uv/)（自动装 Python 3.12）；本地构建前端时还需要 Node.js ≥ 20 与 pnpm。

```bash
git clone https://github.com/lsgoodlionel/Invoice-sorting.git
```

```bash
Invoice-sorting/scripts/setup.sh
```

```bash
Invoice-sorting/backend/.venv/bin/invoice-sorting
```

`scripts/setup.sh` 安装后端依赖（含 OCR）并构建前端。安装前它会**实测官方源与国内镜像（阿里云、清华、npmmirror）的下载速度，自动选最快的源**，并严格按 `uv.lock` / `pnpm-lock.yaml` 的版本安装。可用变量：
`MIRROR`（`auto` 测速 / `cn` 国内镜像 / `global` 官方源）、`NO_OCR=1`（不装 OCR，约 200MB，截图只按文件名识别，可之后[补装](#补装-ocr截图识别)）、
`FRONTEND_BUILD`（`local` 本地构建 / `prebuilt` 用 CI 预构建前端，无需 Node.js / `auto` 先试预构建）、
`SKIP_FRONTEND=1`、`PYPI_INDEX` 与 `NPM_REGISTRY`（手工指定源地址，跳过测速）。

启动后自动打开 <http://127.0.0.1:8765>，只监听本机，不对局域网开放。数据默认在 `~/InvoiceSorting`，
用 `INVOICE_SORTING_DATA_DIR` 可以换地方。升级：`git pull` 后重新执行上面的 `scripts/setup.sh` 与启动命令。
只有自己一个人用、不想每次登录时，启动前设 `INVOICE_SORTING_AUTH_ENABLED=false`。
同前缀（`INVOICE_SORTING_`）的还有 `HOST`、`PORT`、`OPEN_BROWSER`、`WATCH_INBOX`、`FRONTEND_DIST`，
完整清单见 [部署与运维 · 配置项总表](docs/部署与运维.md#六配置项总表)。

### 补装 OCR（截图识别）

截图识别依赖 `rapidocr`、`onnxruntime`、`opencv-python`，下载量约 200MB。用 `NO_OCR=1` 跳过、
或下载中断时可以之后补装，下面的命令按锁文件版本安装（带哈希校验），已装好的包会跳过：

```bash
cd backend && uv export --quiet --frozen --no-dev --no-emit-project --extra ocr --format requirements-txt -o /tmp/ocr-req.txt && uv pip install --python .venv/bin/python --index-url https://pypi.org/simple -r /tmp/ocr-req.txt
```

国内网络把 `--index-url` 换成 `https://mirrors.aliyun.com/pypi/simple`。装好后重启应用即生效，
首次识别会自动下载约 30MB 模型。**服务器上**不用这条命令：重新执行一次一键安装命令、**不带**
`NO_OCR=1`，脚本会把 OCR 依赖与系统库一起补齐。

## 部署到服务器

适用于 Ubuntu 22.04 / 24.04（x86_64 或 arm64）。**安装与升级是同一条命令**，重复执行即升级，
数据与密码都保留，升级前自动备份数据库。也提供 Docker Compose 交付（`deploy/docker/`，镜像非 root 运行、数据挂在 `/data`）。

私有化单账套（默认）：

```bash
curl -fsSL https://raw.githubusercontent.com/lsgoodlionel/Invoice-sorting/main/deploy/install.sh | sudo bash
```

SaaS 多账套：

```bash
curl -fsSL https://raw.githubusercontent.com/lsgoodlionel/Invoice-sorting/main/deploy/install.sh | sudo DEPLOY_MODE=saas bash
```

域名与 HTTPS（域名需已解析到本机，80/443 可访问）：

```bash
curl -fsSL https://raw.githubusercontent.com/lsgoodlionel/Invoice-sorting/main/deploy/install.sh | sudo DOMAIN=invoice.example.com ENABLE_HTTPS=true EMAIL=ops@example.com bash
```

安装命令里**不包含任何账号、密码**，首个管理员一律在网页上设置：单账套打开 `http://服务器IP:8765`，
第一次进入为管理员 `admin` 设置初始密码，之后在「设置 → 用户管理」加人；多账套用**主域名**（不带账套子域名）打开，
第一次进入设置首个**平台管理员**（默认用户名 `admin`）的用户名与密码，设置完即登录，左侧出现「平台」入口。

> 设置之前，任何能访问该地址的人都可以抢先设置，**装完请尽快打开页面完成**。公网部署建议启用 HTTPS。

### 按版本安装与回滚

脚本默认走 `release` 通道：从 GitHub Releases 下载**固定版本**的发布包并逐个校验 SHA-256，任何时候装到的都是同一份通过了完整 CI 的产物，而不是「当时的 main」。当前最新版 **v0.2.0**。

```bash
curl -fsSL https://raw.githubusercontent.com/lsgoodlionel/Invoice-sorting/main/deploy/install.sh | sudo VERSION=v0.2.0 bash
```

把 `VERSION` 换成旧版本号重跑一次就是回滚。查看当前版本：

```bash
cat /opt/invoice-sorting/VERSION
```

想跟随分支最新源码尝鲜调试时加 `CHANNEL=main`（不校验发布包，生产环境别用）。

### 常用部署变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DOMAIN` / `ENABLE_HTTPS` / `EMAIL` | `_` / `false` / — | Nginx `server_name`、Let's Encrypt 证书与通知邮箱 |
| `HTTP_PORT` / `APP_PORT` | `8765`（HTTPS 时 `80`）/ `18765` | 对外端口 / 应用内部端口（仅本机） |
| `CHANNEL` / `VERSION` | `release` / 最新正式版 | 安装来源与版本 |
| `DEPLOY_MODE` | `single` | 部署形态：`single` / `saas` |
| `TENANT_HOST_SUFFIX` | 空 | 仅 SaaS：账套子域名后缀，需泛域名解析与通配符证书 |
| `LICENSE_KEY` / `LICENSE_SERVER` | 空 | 私有化授权密钥与校验服务地址，两项都留空即不校验 |
| `LOG_REPO` / `LOG_TOKEN` | 空 | 诊断包上传的私有仓库与令牌，**留空即不上传** |
| `MIRROR` / `NO_OCR` | `auto` / `0` | 下载源与是否安装截图识别 |
| `INSTALL_DIR` / `DATA_DIR` | `/opt/invoice-sorting` / `/var/lib/invoice-sorting` | 程序与数据目录 |

> 形态、授权、日志这几项**升级时不用重复输入**，脚本会沿用 systemd 单元里已有的值；确实要清空时显式传空值（如 `LICENSE_KEY=`）。
> 完整变量表、Docker 交付、子域名与通配符证书、发布流程见 **[部署与运维](docs/部署与运维.md)**。

## 使用指南

典型流程：

```text
付款后（可选）  清单页按 N「记一笔」：日期、金额、商家 → 状态「已支出」
收到凭证       收集页把发票、订单截图、支付记录一起拖入 → 自动归组、匹配已有记录 →「全部确认」
补齐凭证       把补充材料拖到清单对应行，或再次拖进收集页自动关联 → 状态自动变「凭证齐全」
准备报销       批次页新建批次 →「添加记录」→「生成资料包」→ 把 ZIP 交给财务/经办人
外发后         「标记已外发」填日期、接收人、预约单号 → 状态「已外发」
钱到账后       「登记到账」（可只勾选部分记录）→ 状态「已报销」
```

### 收集：把凭证拖进来

- **拖放导入**：发票（PDF / XML / OFD）、截图（PNG / JPG / WEBP / HEIC）、行程单一次性拖进虚线框，或点击选择文件；逐个文件显示上传与识别进度。
- **自动归为凭证组**：同一笔支出的文件自动归为一组，依据按可靠程度依次为——**订单号一致**（发票备注的订单号 = 订单截图的订单编号）、**文件名一致**（去掉「发票/订单/银行交易/收据」、金额、地区后剩余相同，如 `办公-20260312-升降桌-459-江苏.pdf` 与 `办公-20260312-升降桌-交易订单.PNG`）、**金额与日期一致**（金额相同、日期相差 3 天内且商家相近）、**境外订单与银行交易**（日期相近，卡号末四位一致更可靠）、**住宿与交通**（酒店发票与订单按金额、酒店名、日期归组，入住前后 1 天内往返该城市的车票机票并入）。除「一张住宿发票 + 若干交通票」外，每组最多一张发票；订单号不同的两套凭证不会混在一起。
- **判断是否首次上传**：每组都会去找已有记录。订单号或文件名对得上的直接建议「挂到 #id」；否则按金额、日期、商家、该记录是否正好缺这类凭证打分，分数够高且明显领先才建议挂上，其余列为候选；都没有则建议新建。同一订单的同类凭证已上传过会提示「可能重复」并默认跳过。
- **导入确认表（按组）**：每组显示文件卡片、关联依据、识别出的日期、商家、人民币金额与原币、分类、网购、免发票，均可修改。文件卡片可改类型、「移到其他组」、「拆为单独一组」；「操作」可选新建记录、挂到建议或候选记录、搜索其他记录、留在待归属。黄色提示要留意（购方不一致、外地发票需订单、可能重复）。核对无误点 **全部确认**。
- **收件箱自动导入**：把文件放进数据目录下的 `收件箱/`，几秒后自动按组处理：强匹配的挂上去，金额和日期齐全的新建，其余留在待归属；无法处理的移到 `收件箱/无法处理/` 并附说明。

**分类是怎么猜出来的？** 优先级从高到低：**商品记忆**（你亲手改过的同名商品）→ **文件名分类词**（`办公-…`、`图书-…` 这类前缀，代表你整理文件时的明确意图）→ **发票税收分类简称**（`*印刷品*` → 图书，客观且不受商家影响）→ **商家记忆**（该销售方上次用的分类；京东、圆迈等综合电商平台除外，它们什么都卖）→ **关键词**（商品与销售方名称中命中最长的那个，「打印纸」优先于「打印机」）→ 都不命中归为「其他」。
改错了就在确认表或详情里改一次，系统会记住。关键词在「设置 → 分类」里增删；规则改过之后，「设置 → 分类整理」可以列出按新规则应当改分类的旧记录，勾选后批量改正。

### 待归属：还没挂上的文件

待归属是**已导入但还没挂到任何记录**的文件：确认时选了「留在待归属」、识别不出内容、或只有截图还找不到对应记录。在收集页下方，每个文件显示识别结果和**建议记录**（如「建议挂到 #12 京东 ¥459（订单号一致）」），点 **采纳** 即归属；勾选多个可批量**生成记录**（按凭证组规则新建或挂上）、**归属到记录…**（手工选，可同时设类型）、**重新识别**（识别规则更新后重新解析）、**删除**（移入回收站）。已归属的文件想换记录，在记录详情的附件列表里「移回待归属」再重新归属即可。

### 清单：跟进每笔支出

- **筛选**：周期（本月 / 本季度 / 本年 / 上月 / 上季度 / 全部 / 自定义）、日期口径、分类、经费项目、搜索（商家 / 摘要 / 发票号），条件保存在网址里可收藏；上方状态条显示 6 个状态的数量与金额，点一下即按该状态筛选。
- **表格**：日期、商家·摘要、分类、金额、状态、「缺 N 项」徽标、所属批次。
- **详情抽屉**（点击任一行）：顶部状态步进条可手动设置状态（带「手动」标记，能「恢复自动」）；基本信息（日期、金额、商家、摘要、分类、经费项目、付款方式、网购、备注）离开输入框即自动保存；凭证清单每项显示是否已有与提示，缺项行内直接拖入文件上传，也可标「不需要」并写原因；还有该分类的办理路径（一键复制）、附件预览与改类型、时间线（时间、自动/手动、操作人），以及作废（需填原因）与删除。住宿记录额外显示酒店订单信息与金额构成。
- **批量与快捷键**：勾选多条后按 `B` 或点「加入批次」；`N` 记一笔，`/` 搜索，`Esc` 关闭抽屉。

**境外订阅（无发票）**：订单/收据与银行交易一起上传（或先后上传）会归为一组并标记 **免发票**：
人民币金额取银行入账，原币（如 US$20.00）一并保存；凭证清单改为要求订单或收据、银行卡交易明细（必需）与情况说明（建议）；
清单里显示「免发票」徽标，状态第二步显示为「已收凭证」。也可以在记录详情里手动打开这个开关并设币种。

**差旅住宿**：一笔住宿报销 = 酒店发票 + 酒店订单 + 往来交通凭证，可以一次上传，也可以分多次、由不同人补传。
酒店订单读出酒店、城市、入住离店日期、晚数、房间数，交通票读出出发到达地与车次航班，
摘要形如「某某酒店 1晚 + 交通 2 张」。之后补传的交通票发票挂上后，记录金额自动加上票价并在时间线记
「并入交通票 ¥xx」；手动改过金额的记录不会被自动调整。

**开票地区**：数电发票号码第 3–4 位是开票税务机关所在省份（如 `25`**`31`**`7…` 上海、`25`**`11`**`7…` 北京），
旧版发票看发票代码，都没有时看销售方信用代码。与「设置 → 本地地区」（默认上海）不同即为**外地发票**，
自动增加必需凭证「订单明细」；销售方属于「已带明细平台」（默认京东、当当、圆迈）时可免。

### 批次：打包外送

- **新建与添加记录**：批次填名称（如「2026-09 科研A 第1批」）与可选经费项目。「添加记录」列出未分批、未作废的记录（默认只显示与批次相同经费项目的，可切换全部），弹窗顶部能按日期周期（本月、本季度、近 3/5/10 年或自选起止）与日期口径（支出/开票/外发/到账）、分类、经费项目、状态、缺不缺凭证筛选，显示条数与合计，可「全选当前筛选结果」。记录仍缺必需凭证、或经费项目与批次不一致时会提示原因，确认后可「仍然加入」。
- **批次筛选**：左侧批次列表按状态（待外发/已外发/部分到账/已到账）和日期周期（口径：创建/外发/到账日期）筛选，显示批次数与合计金额，条件保存在地址栏。
- **生成资料包**：选分组方式后生成 ZIP，每次生成新文件、保留历史包，可随时重新下载或删除（记录与凭证不受影响）。包内是 `00_报销汇总表.xlsx`（序号/日期/商家/摘要/分类/金额/发票号/附件清单/缺项/备注 + 合计与分类小计）、`01_打印版_全部材料.pdf`（按序号合并发票 → 订单 → 支付记录 → 验收单，图片自动排成 A4）、`02_发票原件/`（未经修改的原件，文件名为 `序号_分类_金额_商家_发票号`）和 `03_支撑材料/`。序号贯穿三者，方便财务对照。支撑材料两种分组方式只影响目录结构：**按支出分组**（`01_京东××店_960.00/订单明细_1.png`）适合逐笔核对装订，**按材料类型分组**（`订单明细/01_京东××店_960.00_1.png`）适合报销系统按附件类型分别上传。
- **标记已外发**：填外发日期、方式、接收人、外部单号（如预约报销单号），批次内记录变为「已外发」，之后不能再增删记录。
- **登记到账与重新打开**：全部或勾选部分记录到账，批次显示「部分到账」/「已到账」；登记有误时重新打开回到待外发状态，记录状态按凭证清单重算。

### 统计

选周期和日期口径（支出 / 开票 / 外发 / 到账日期），页面标题会注明「按××日期统计」。
顶部四个数字：本期支出（不含作废）、待处理（已支出 + 已开票 + 凭证齐全）、在途（已外发未到账）、
已报销（实际到账），作废金额单列。下面是交叉表（按分类 / 经费项目 / 商家 / 月份分组 × 状态，
点金额跳转到对应明细，数字与清单页同条件合计一致）与按月趋势柱状图，「导出 Excel」输出汇总与明细。

### 设置

| 设置项 | 说明 |
| --- | --- |
| 基本 | 购方抬头与税号（与发票购买方比对，不一致标黄）、超期提醒天数（默认 30 天）、本地地区（默认上海）、已带明细平台 |
| 分类 / 经费项目 | 分类的名称、颜色、识别关键词、办理路径（删除为归档）；经费项目的经费号、名称、负责人（也可在记录详情与批次里直接新建） |
| 凭证清单规则 | 分类（或通用）、材料类型、必需/建议、触发条件（金额≥、金额<、仅网购、仅外地发票、排除已带明细平台、免发票记录、发票内容含/不含关键词）、提示文字 |
| 分类整理 | 按当前规则重算旧记录的分类，列出建议并批量改正（仅管理员） |
| 用户管理 / 运行日志与诊断 | 添加用户、重置密码、改姓名与角色、停用启用；生成脱敏诊断包（都仅管理员） |
| 登录与安全 | 修改自己的密码、退出登录；单账套部署还显示数据目录与备份入口 |

**用户与权限**：管理员可以做全部操作；普通用户能收集凭证、处理记录、打包批次、看统计、新建经费项目、改自己的密码，
但看不到用户管理，系统设置只读。系统始终保留至少一名启用中的管理员，管理员不能停用自己或取消自己的管理员身份。
停用用户或重置密码后，该用户所有设备立即退出。登录状态保存 30 天（使用时自动续期）；
密码加盐哈希存储，同一 IP 15 分钟内输错 5 次锁定 15 分钟，会话 Cookie 不可被网页脚本读取。

## 多账套与平台运营

只有 `DEPLOY_MODE=saas` 才有这一层；单账套部署完全看不到。

- **数据隔离**：控制库 `control.db` 存账套、账号、套餐、用量与授权记录；每个账套有自己独立的业务库与文件目录（`tenants/<账套标识>/`）。
- **登录与加入**：账号全局唯一，登录后进入所属账套，属于多个账套时可在界面切换；配置了 `TENANT_HOST_SUFFIX` 后 `t1.example.com` 直接定位到账套 `t1`（需泛域名解析，HTTPS 还需通配符证书）。新同事用管理员生成的**邀请码**在登录页加入，已有账号填自己的用户名密码即可加入新账套。
- **平台运营后台**（`/platform`，仅平台管理员可见）：开通与维护账套（改套餐、到期日、停用与恢复）、套餐管理、成员与邀请码、私有化授权记录、用量概览、导出账套数据包。
- **套餐额度与状态**：限成员数、存储空间、当月新增记录数，**只拦「会让用量变大」的动作**（新建记录、上传文件、添加成员），修改与删除永远放行，免得超限后连清理自救都做不到；超限提示会说明超的是哪一项、上限多少、当前多少。停用、关闭或订阅到期的账套转为**只读**——可登录、查看、导出与备份，不能新增和修改，数据不会被删除。

首个平台管理员在网页第一次打开时设置（默认用户名 `admin`）。忘记密码、或服务器上没有浏览器时，用命令行补一个：

```bash
sudo -u invoice env INVOICE_SORTING_DATA_DIR=/var/lib/invoice-sorting /opt/invoice-sorting/app/backend/.venv/bin/invoice-sorting grant-platform-admin --username ops
```

账套开通、子域名接入与套餐管理的完整步骤见 [部署与运维 · SaaS 多账套](docs/部署与运维.md#四saas-多账套)。

## 私有化交付与授权

需要定期在线校验的私有化交付，在安装时带上 `LICENSE_KEY` 与 `LICENSE_SERVER`（升级时不必重复输入）。
两项任意一项为空时程序**完全不做校验、也不发起任何网络请求**。

工作方式：实例首次启动生成 `instance_id`；每 24 小时（`CHECK_INTERVAL_HOURS`）向控制面校验一次，返回 Ed25519
签名的令牌落到本地；令牌到期后再宽限 14 天（`GRACE_DAYS`）容忍断网与续期延迟，期间界面顶部提示；宽限期满转**只读**
（可登录、查看、导出、备份，数据不删），密钥被停用或无效则立即只读并说明原因。授权状态在「设置」页可见，
管理员可点「重新检查」立即重新校验。

> 🚨 **仓库里内置的是测试公钥，正式发布前必须更换。** 对应的测试私钥为了跑测试而有意公开在
> `backend/tests/license_helpers.py` 里，只要还用内置公钥，任何人都能自己签出「合法」令牌，授权校验形同虚设。
> 它只影响「防止私有化包被无限复制」这一件事，不影响功能、数据安全与登录鉴权。
> 启用了在线校验却仍用内置公钥时，服务启动会在日志里告警，`GET /api/license/status` 的 `uses_test_key` 为 `true`。
> 生成密钥对、替换公钥常量、把私钥只注入控制面的完整步骤见
> [部署与运维 · 私有化授权](docs/部署与运维.md#七私有化授权)。**私钥不要写进任何文件或提交到仓库。**

**账本搬迁**：在「设置 → 备份与搬迁」一键导出整本账（记录、附件原件、分类与项目、凭证清单、批次、时间线），
在另一个账户、账套或服务器上同一位置上传导入。本机、私有化、SaaS 之间可以互相搬。导入前先给预览，确认后才写入，失败整体回滚：

- **合并**（默认）：并入现有账本，按附件内容与发票号去重，已有的跳过，**不修改你已有的任何记录**；分类与项目按名称对应，冲突保留本地。重复导入同一个包不会产生重复数据。
- **覆盖**：整本替换为包内容，执行前自动备份，需要输入账套名称二次确认。

包里的上传人、操作人按用户名匹配本地账号，匹配不到就建一个停用的占位账号，历史记录仍显示是谁传的。
网页上传支持 2 GB 以内的包（分片上传，显示进度）；更大的包在服务器上用命令行：

```bash
sudo -u invoice env INVOICE_SORTING_DATA_DIR=/var/lib/invoice-sorting /opt/invoice-sorting/app/backend/.venv/bin/invoice-sorting import-tenant --in 账本.zip --mode merge
```

先加 `--dry-run` 看预览不写入；`--mode replace` 为覆盖。多账套部署要加 `--slug 账套标识`，本机把命令前缀换成 `backend/.venv/bin/invoice-sorting`。
设计与规则见 [账本搬迁](docs/账本搬迁_设计.md)，运维步骤见 [部署与运维 · 账套搬迁](docs/部署与运维.md#八账套搬迁)。

## 运维与故障排查

服务名就是 `invoice-sorting`，`sudo systemctl status|restart invoice-sorting` 看状态与重启，实时日志：

```bash
sudo journalctl -u invoice-sorting -f
```

服务器上的收件箱在 `/var/lib/invoice-sorting/收件箱/`，可以用 `scp` / `rsync` 把发票批量传进去自动导入。

### 运行日志与诊断包

应用日志写在 `数据目录/日志/app.log`（按大小轮转，级别由 `INVOICE_SORTING_LOG_LEVEL` 控制）。
服务器出问题时不用手工复制 journalctl，生成一个**脱敏诊断包**发给开发即可（管理员也能在「设置 → 运行日志与诊断」里点按钮生成）：

```bash
sudo -u invoice /opt/invoice-sorting/app/backend/.venv/bin/invoice-sorting diagnose --reason=manual
```

命令会打印 zip 路径（默认在 `数据目录/日志/诊断包/`，只保留最近 10 个）。包里是版本、系统与磁盘信息、应用日志与
systemd 日志的尾部，以及环境变量的**名字和「已设置/未设置」**；邮箱、手机号、证件号、卡号、发票号、金额、商家与人名、
公网地址、密钥令牌密码都会替换成占位符，打包后还会再自检一遍，发现残留就拒绝上传。

**默认不上传到任何地方**，诊断包只留在本机。希望出故障时自动发到自家的**私有** GitHub 仓库，就配置
`INVOICE_SORTING_LOG_REPO` 与 `INVOICE_SORTING_LOG_TOKEN`（安装脚本对应 `LOG_REPO` / `LOG_TOKEN`）；令牌只需要该仓库的
Contents 读写权限，只从环境变量读取，不落库、不写日志、不进诊断包，清空仓库配置就立刻停止上传。
细节见 [日志与故障上报 · 设计](docs/日志与故障上报_设计.md)。

### 常见问题

**升级后服务起不来、日志里有 `bad marshal data`（或页面 502）？** Python 字节码缓存损坏。新版脚本会先停服务、装完自检并自动修复；已经遇到时清空 `/var/cache/invoice-sorting/pycache/` 后重启服务，仍不行就删掉虚拟环境重跑安装命令（数据不受影响）。逐条命令见 [部署与运维 · 故障排查](docs/部署与运维.md#122-bad-marshal-data字节码缓存损坏)。

**界面提示「只读，无法新增和修改」？** 三种可能：私有化授权过期或被停用、账套被停用或关闭、订阅到期。数据不会丢，查看、导出和备份都还能用；打开「设置」页看具体原因，续期或联系平台管理员恢复后即可。没配授权密钥、也不是多账套的部署不会出现这个提示。

**忘记登录密码？** 普通用户请管理员在「设置 → 用户管理」重置。管理员 `admin` 在服务器上执行下面的命令清除密码，然后重新打开网页设置新的初始密码（admin 已登录的设备会全部退出），加 `--user 用户名` 可指定其他用户：

```bash
sudo -u invoice env INVOICE_SORTING_DATA_DIR=/var/lib/invoice-sorting /opt/invoice-sorting/app/backend/.venv/bin/invoice-sorting reset-password
```

**发票被分到「其他」？** 在确认表或记录详情里改成正确分类，系统会记住这个商品和商家；也可以在「设置 → 分类」补关键词，再用「分类整理」批量改正旧记录。

**同一套凭证分开上传会不会重复建记录？** 不会。后上传的文件按订单号、文件名、金额日期匹配到已有记录并建议挂上；同一订单的同类凭证再次上传会提示「可能重复」。建议不对时在确认表里改选记录。

**批次打包时找不到已上传的发票？** 发票要先加入批次：批次页「添加记录」勾选，或清单页勾选后「加入批次」。已在其他批次、已作废的记录不会出现在可添加列表里。

**识别出来的金额或日期不对？** 确认表里可以直接改，确认后在记录详情里也能改。识别不出的发票会作为附件导入，手工填写即可。欢迎把识别有误的发票版式反馈到 Issues。

**怎么迁移到另一台机器？** 停止应用后复制整个数据目录（服务器上注意 `chown -R invoice:invoice /var/lib/invoice-sorting`），或用「设置 → 备份与搬迁」导出后在新机器上导入（见[私有化交付与授权](#私有化交付与授权)）。

## 核心概念

**支出记录**是一次花钱的事（如「9 月 15 日 京东 鼠标 ×2 960 元」），包含基本信息、附件、凭证清单、状态与时间线；
**报销批次**是一次外送给财务/经办人的资料集合，包含若干支出记录、打包历史、外发与到账信息。

### 状态

| 状态 | 含义 | 自动进入条件 |
| --- | --- | --- |
| 已支出 | 钱花了，发票还没到 | 新建记录且没有发票 |
| 已开票 | 发票已收到并确认（免发票记录显示为「已收凭证」） | 有已确认的发票附件；免发票记录有订单/收据或支付记录 |
| 凭证齐全 | 需要的材料都有了 | 凭证清单必需项全部「已有」或「不需要」 |
| 已外发 | 已交给财务/经办人 | 所在批次标记已外发 |
| 已报销 | 钱已到账 | 所在批次登记该记录到账 |
| 不报销/作废 | 个人承担、重复、退货等 | 仅手动设置，需填原因 |

手动设置的状态不会被自动回退；作废或删除记录会自动移出待外发批次，已外发批次中的记录需先重新打开批次。

### 默认分类与凭证清单

| 分类 | 默认必需材料（在通用规则之外） | 办理提示 |
| --- | --- | --- |
| 办公用品 | 网购或 ≥500 元：订单明细 | 不在设备与实验室平台填报 |
| 易耗品 / 低值品 / 材料 | 订单明细、验收单 | 打印验收单，填「材料费」 |
| 设备 | 申购单、验收单、支付记录 | 单价 ≥1000 元先申购，申购日期早于购买日期 |
| 软件服务 | 订单、软件服务报账单、验收单 | 填「委托其他业务费」 |
| 图书 | 购书清单/送货清单；≥500 元（建议）图书馆验收单 | 单册或单套 ≥500 元图书馆验收；非书店购买附电脑小票 |
| 印刷快递 | （建议）明细 | 票面已开明细可免 |
| 差旅交通 | 交通票：行程单；住宿：酒店订单 + 往来交通凭证（往返酒店所在地的火车/飞机/汽车/轮船票或行程单） | 个人出行与节假日不报 |
| 餐饮会议 | （建议）工作餐单或会议材料 | 工作餐 50 元/人/餐 |
| 其他 | — | — |

通用规则：需发票（免发票记录除外）；金额 ≥1000 元需支付记录；金额 ≥30000 元需合同；
外地发票需订单明细（已带明细平台可免）；免发票记录需订单或收据、银行交易明细，建议附情况说明。

## 数据与备份

```text
数据目录（本机 ~/InvoiceSorting，服务器 /var/lib/invoice-sorting）
├── invoice.db        业务数据库（SQLite）
├── control.db        账号、账套、套餐与授权（多账套部署的业务数据在 tenants/<账套标识>/ 下）
├── 收件箱/            放进来的文件自动导入
├── 文件库/            2026/09/20260915_京东××店_易耗品_960.00_E0001/ 下是该笔支出的全部原件
│   ├── 待归属/        还没挂到任何记录的文件
│   └── .回收站/        删除的记录与附件
├── 日志/              app.log 与诊断包/
├── 资料包/            生成的报销资料 ZIP
└── 备份/              数据库快照（设置页「创建数据库快照」、服务器升级前自动备份）与账本导出包
```

- 原始发票文件入库后不会被修改；改记录的日期、商家、分类或金额时，文件夹自动重命名。金额以「分」为单位整数存储，不存在浮点误差。
- **两种备份别混淆**：「设置 → 备份与搬迁」里的**完整备份**（导出账本）含全部附件，下载到你的电脑，能防硬盘损坏，也能导入到别处；**数据库快照**只含数据库、不含附件、留在服务器上，只适合做有风险的操作前留底。
- 本机也可以直接复制整个数据目录，建议放在 Time Machine / 网盘同步范围内；服务器上的备份与恢复见 [部署与运维 · 备份与恢复](docs/部署与运维.md#九备份与恢复)。
- **所有数据只保存在本机或你自己的服务器上**，不会发送到任何外部服务；唯一的例外是显式配置了日志仓库后上传的脱敏诊断包。

## 开发

后端 Python 3.12 · FastAPI · SQLAlchemy · SQLite，前端 React · TypeScript · Mantine · TanStack Query · Vite。
`backend/src/invoice_sorting/` 按领域分模块：`expenses` `attachments` `checklist`（记录、文件入库、凭证清单）、
`parsers` `evidence` `importer`（发票解析、非发票凭证识别、按凭证组导入与匹配）、
`batches` `exporter` `stats` `settings`、`auth` `users` `invites`、
`control` `tenancy` `quota` `platform_admin`（控制库与租户运行时、额度、运营后台）、
`licensing` `migration` `diagnostics`。`frontend/` 是界面，`deploy/` 放一键安装脚本与 Docker 交付。

```bash
uv run --project backend pytest
```

```bash
uv run --project backend ruff check backend/src backend/tests
```

```bash
pnpm --dir frontend test
```

```bash
pnpm --dir frontend build
```

前端开发服务器（把 `/api` 代理到 `127.0.0.1:8765`）用 `pnpm --dir frontend dev`，后端用
`uv run --project backend invoice-sorting` 启动（同时托管 `frontend/dist`）。
命令行子命令共五个：`reset-password`、`diagnose`、`grant-platform-admin`、`export-tenant`、`import-tenant`。

测试样本均为虚构发票（`backend/scripts/make_invoice_fixtures.py` 生成），**请勿提交真实票据、密钥或令牌**。
