# 账本一键导入导出 · 设计

编制日期：2026年9月21日

## 1 目标

把一个账本（记录、附件原件、分类与项目、凭证清单、批次、时间线）整体打包带走，并导入到**另一个账户、另一个账套、另一台服务器**——本地部署与 SaaS 部署之间双向可搬。

已有能力（v0.2.0）：`export-tenant` / `import-tenant` 命令行，按**账套整体替换**。本次在其之上补两件事：

1. **合并导入**：并入一个已经有数据的账本，自动去重，不覆盖已有内容。
2. **网页一键**：设置页直接导出下载、上传导入，普通管理员不用登服务器。

## 2 包格式

沿用现有搬迁包（`manifest.json` + `data/` 下的数据库与文件库），新增 `ledger.json` 描述导出范围与来源：

```json
{
  "kind": "ledger",
  "source": {"deployment": "saas|single", "tenant": "客户甲", "exported_by": "张三", "app_version": "0.2.1"},
  "scope": {"records": 1234, "attachments": 3456, "batches": 12, "from": "2024-01-01", "to": "2026-09-21"}
}
```

旧包（没有 `ledger.json`）仍可导入，按整账套包处理。

## 3 导入模式

| 模式 | 语义 | 入口与保护 |
| --- | --- | --- |
| **合并**（默认） | 把包里的内容并入目标账本，已存在的跳过 | 网页与命令行；导入前先给预览 |
| **覆盖** | 目标账本整体替换为包内容 | 需勾选并输入账套名二次确认；执行前自动整包备份到 `备份/` |

两种模式都在导入前生成**预览**（dry-run）：将新增多少记录与附件、跳过多少重复、有哪些冲突需要人工确认；用户确认后才真正写入。

## 4 合并规则

### 4.1 去重

| 对象 | 判重依据 | 命中后 |
| --- | --- | --- |
| 附件 | `file_key`（文件内容哈希，已有字段） | 跳过文件与数据库行，沿用本地已有附件 |
| 发票 | 发票号码 | 视为同一张发票，不重复导入 |
| 记录 | 同发票号；或（金额 + 支出日期 + 商家）且附件集合有交集 | 跳过，并在报告中列出 |
| 分类 / 经费项目 | 名称（去空格） | 复用本地同名项；勾选「同时导入系统设置」时分类的颜色、关键词、办理路径以包为准 |
| 凭证规则 / 关键词 / 分类记忆 | 内容相同即跳过；冲突时默认**以包为准**（见 4.5），不勾选则**保留本地** | 报告中列出改写或未采纳的项 |

### 4.2 标识重映射

包内所有主键在导入时重新分配，按旧 → 新映射表改写外键（附件、发票与凭证数据、清单项、时间线、批次成员、导出记录）。**绝不沿用包内的 id**，避免与本地冲突。

### 4.3 人

包里的上传人与操作人按**用户名**匹配本地账号：匹配到就用本地账号；匹配不到则创建一个**停用状态**的占位账号（保留姓名，不能登录），使历史记录仍显示"谁传的、谁改的"。占位账号在用户管理里标注来源为导入。

### 4.4 批次与资料包

- 批次连同成员关系一起导入；名称冲突时追加来源后缀（如"2026-09 第1批（来自 客户甲）"）。
- 已生成的资料包 ZIP **不导入**（可随时重新生成），只保留生成记录。

### 4.5 同时导入系统设置（include_settings）

导入请求（网页 `complete` / `confirm`、命令行 `import-tenant`）带 `include_settings`，**默认 true**。
为 true 时合并模式下以下内容**以导入包为准**，报告中动作记为「更新」（`updated`）：

| 内容 | 规则 |
| --- | --- |
| 用户设置（报告 `settings` 分区「系统设置」） | 只认白名单：`buyer_name` 报销抬头、`buyer_tax_id` 买方税号、`local_region` 本地地区、`detail_platforms` 已带明细平台、`overdue_days` 超期提醒天数。只导入包里实际保存过的键（包里没设过的不清空本地）；取值按设置页规则校验，不合法记为失败并保留本地。明细为「中文名：原值 → 新值」 |
| 同名分类 | 颜色、关键词、办理路径说明改为包内的值；名称、排序、归档状态不动 |
| 凭证规则 | 按「分类 + 附件类型」对位：包内某位的规则与本地同位规则不同 → 本地该位整体替换为包内的；包里有而本地没有的位新增；包里没有的位不动 |
| 分类记忆 | 同一商家/商品本地记为别的分类 → 改为包内的分类；本地独有的记忆保留 |

- **永不导入**：内部版本标记（`keywords_version`、`rules_version`、`classification_memory_version` 等 `*_version`）、
  旧版密码哈希，以及任何与本机路径、部署、认证、授权、日志相关的配置——白名单之外的键一律忽略。
- 地区设置改变后，导入提交后自动重算未完成记录的凭证清单（与设置页保存地区效果一致；重算失败不回滚导入，只提示）。
- 为 false 时保持原行为：冲突保留本地；`settings` 分区把差异列为「跳过」，便于用户决定要不要勾选。
- **覆盖模式**整体替换数据库，设置本来就以包为准，`include_settings` 不起作用；预览与结果的提示中写明这一点。

## 5 网页入口

「设置 → 备份与搬迁」（管理员可见）。**备份即导出，只有一个按钮**；原「数据库快照」已移除，避免两种备份让人困惑
（升级脚本在升级前自己用 `sqlite3` 备份数据库，不受影响）：

- **立即备份（导出）**：一键生成完整包（整个业务数据库，含系统设置、分类、规则与记忆 + 全部附件 + 可选的资料包），
  后台打包，完成后下载到本机；同一个包同时留在服务器上**该账套自己的** `备份/账本备份/`（单账套即 `数据目录/备份/账本备份/`，
  SaaS 为 `tenants/<账套>/备份/账本备份/`），按账套各自保留最近 10 份，可在页面上列出并再次下载
  （`GET /api/backup/packages`、`GET /api/backup/packages/{name}`）。每个包旁边的同名 `.json` 侧车记录是否含资料包、文件数与导出人。
  平台后台替某账套导出的包仍放在平台根目录 `备份/租户导出/`，不进账套自己的列表。
  升级前网页导出的旧包留在 `备份/租户导出/`，不自动迁移，需要可手动移动到 `账本备份/`。
- **账号不在包里**：账号与密码哈希在 `control.db`，账本备份不包含它。同机恢复不影响现有账号；
  换机器时按 4.3 匹配或建占位账号（覆盖模式按包内用户建号，但密码通常需重设）。单账套要连账号一起带走，
  请连同 `control.db` 与 `secret.key` 一起复制（部署与运维 9.2）。
- **SaaS 平台数据库**（`control.db`）由平台管理员在运营后台单独备份（`/api/platform/backups`），存放在平台根目录 `备份/平台/`；
  单账套部署没有这个入口。
- **导入**：选择文件 → **分片上传**（每片 8 MB，显示进度，支持失败重试该片）→ 服务端合并校验 → 预览（可切换「同时导入系统设置」）→ 确认后执行 → 结果报告（新增/更新/跳过/失败明细，可下载）。
- 上传的临时分片放在 `data_dir/.导入暂存/`，超过 24 小时未完成自动清理。

## 6 命令行

```
invoice-sorting export-tenant [--slug x] [--out x.zip] [--no-packages]
invoice-sorting import-tenant --in x.zip [--slug y] [--mode merge|replace] [--dry-run] [--no-settings]
```

`--no-settings` 等同网页取消勾选「同时导入系统设置」。

`--mode` 默认 `merge`；`--dry-run` 只输出预览报告不写入。原有行为（整套替换）等价于 `--mode replace`。

## 7 安全

- 包来自外部，一律视为不可信输入：沿用现有 zip 防护（防目录穿越、成员数与体积上限、逐文件 SHA-256 校验），并且**只解包 manifest 列出的成员**。
- 合并导入只按白名单导入用户设置（4.5，可关闭）；认证配置、授权、日志与部署相关配置、内部版本标记一概不动。
- 备份包的列表与下载只看当前账套自己的目录，文件名按白名单正则校验并确认解析后仍在该目录内，其他一律 404。
- 导入需要管理员权限；SaaS 下只能导入**当前账套**，跨账套导入走平台后台。
- 覆盖模式二次确认 + 自动备份；导入过程先写暂存再整体切换，失败不留半个账本。
- 导入报告不包含令牌、密码等敏感信息。

## 8 限制

- 单包上限 2 GB（再大建议在服务器上用命令行）。
- 合并导入不改变本地已有**记录**的任何字段，只做新增；设置类内容可按 4.5 以包为准；整本以包为准时用覆盖模式。
- 跨版本：包的 schema 版本高于当前程序时拒绝导入并提示先升级。
