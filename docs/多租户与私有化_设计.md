# 多租户 SaaS 与私有化交付 · 设计

编制日期：2026年9月20日

## 1 目标与形态

同一套代码支持两种形态，由 `INVOICE_SORTING_DEPLOYMENT_MODE` 决定：

| 形态 | 值 | 说明 |
| --- | --- | --- |
| 单租户（默认） | `single` | 现有私有化/本机部署，界面不出现“租户”概念，升级后行为与现在一致 |
| 多租户 SaaS | `saas` | 一套服务承载多个租户，控制面统一管理开通、套餐与用量 |

隔离方式：**控制面共享库 + 每租户独立业务库与文件目录**。租户接入以**统一域名 + 登录后按账号归属**为主，保留**子域名**可选（配置 `tenant_host_suffix` 后 `t1.example.com` 直接定位租户）。本版 SaaS 为**开通制**，不含在线支付。

## 2 目录与数据库

```
data_dir/
  control.db              控制库（租户、账号、会话、套餐、用量、授权）
  tenants/<slug>/         每租户一套，结构与现在的 data_dir 完全一致
    invoice.db  文件库/  资料包/  备份/  收件箱/
```

单租户模式下仍有 `control.db`，其中只有一个租户（slug `default`），业务数据保留在原 `data_dir` 根目录，老部署无需搬动文件。

### 2.1 控制库

| 表 | 关键字段 |
| --- | --- |
| `tenant` | slug（唯一，小写）、name、status（active/suspended/closed）、plan_id、expires_on、data_dirname、created_at |
| `plan` | code、name、max_users、max_storage_mb、max_expenses_per_month、features(JSON) |
| `account` | username（全局唯一，小写，可为邮箱）、display_name、password_hash、is_platform_admin、is_active、last_login_at |
| `membership` | account_id、tenant_id、role（admin/member）、is_active |
| `auth_session` | token_hash、account_id、tenant_id（当前所选租户）、expires_at |
| `invite` | code、tenant_id、role、expires_on、used_by |
| `usage_snapshot` | tenant_id、day、users、storage_bytes、expenses_created |
| `license_record` | 控制面签发的授权：license_key、客户名、max_users、valid_until、status |

### 2.2 租户库

现有 17 张表结构不变。`app_user` 改为控制面账号在租户内的**镜像**：`id` 等于 `account_id`，同步 username/display_name/role/is_active，`password_hash` 不再使用（登录统一走控制面）。这样附件上传人、时间线操作人、导出等既有外键与展示逻辑都不用改。

## 3 请求流程

1. 认证中间件读会话 → 账号 + 会话中的当前租户。
2. 租户解析优先级：子域名（配置了 `tenant_host_suffix` 时）→ 会话中的 tenant_id → 该账号唯一的租户。账号属于多个租户时提供切换接口，切换需校验 membership。
3. `TenantRuntime` 按 slug 缓存租户的 Settings、engine、session_factory（LRU + TTL，带上限）；首次访问时建库、补列、种子数据。
4. 现有 `SessionDep`/`ConfigDep` 改为返回**当前租户**的会话与配置，业务代码基本不动。
5. 单租户模式：固定 slug `default`，不解析子域名、不提供切换，界面不出现租户字样。

## 4 套餐额度与租户状态

写操作前校验，超限返回明确文案（前端按现有 errorGuide 展示）：

- 租户 `status != active` 或已过期 → **只读模式**：可登录、可查看、可导出，不可新增与修改。
- 用户数 > `max_users` → 不能再添加成员。
- 存储 > `max_storage_mb` → 不能再上传文件。
- 当月新增记录 > `max_expenses_per_month` → 不能再新建记录。

用量每日快照，运营后台可见；超限提示区分“已达上限”和“即将到期”。

## 5 平台运营后台

`/api/platform/*`（仅 `is_platform_admin`）：租户列表与创建、改套餐与到期日、停用与恢复、成员管理与邀请码、用量查看、导出租户数据。前端新增 `/platform` 页面，普通用户不可见。

租户内管理仍是现有「设置 → 用户管理」，管理员只管自己租户的成员。

## 6 私有化授权（在线定期校验）

- 安装时填写 `license_key`；实例首次启动生成并持久化 `instance_id`。
- 每 24 小时向 `license_server`（默认 SaaS 控制面）请求校验：提交 license_key、instance_id、版本、用户数；返回 **Ed25519 签名**的令牌 `{valid_until, max_users, features, issued_at}`，本地落库。
- **宽限**：令牌 `valid_until` 之后再宽限 14 天（容忍断网与续期延迟），期间界面顶部提示。
- 宽限期满 → 只读模式（数据不删，可导出）。密钥被停用或无效 → 立即只读并明确原因。
- 公钥内置于代码，私钥只在控制面；校验失败区分“网络不可达”（继续宽限）与“授权无效”（立即生效）。
- 单机/内网可申请离线授权文件作为例外，本版不做。

## 7 数据搬迁

- `invoice-sorting export-tenant --slug x --out x.zip`：`manifest.json`（应用版本、schema 版本、租户信息、校验和）+ 数据库一致快照（`VACUUM INTO`）+ 文件库 + 资料包。
- `invoice-sorting import-tenant --in x.zip --slug y`：校验版本与 slug 冲突，导入后自动补列迁移。
- 运营后台与私有化设置页提供按钮触发（异步任务 + 下载链接）。
- 用途：SaaS ↔ 私有化互相搬迁、客户自助备份、故障恢复。

## 8 升级与兼容

- 现有单租户部署升级后：自动建 `control.db`，把 `app_user` 中的账号迁到 `account` + `membership`（保持 id 不变），会话表迁到控制库，业务库原地不动。用户无感，密码不变。
- 回滚：控制库为新增文件，业务库未改结构，回退到旧版本仍可运行。
- 所有新表与新列沿用现有 `add_missing_columns` 轻量迁移策略。
