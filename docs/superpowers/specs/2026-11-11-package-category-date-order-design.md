# 资料包按分类和日期排序设计

## 背景

当前批次生成资料包时，所有记录统一按消费日期 `spent_on`、记录 ID 排序并编号。用户选择“按材料类型分组”后，希望生成的全部材料先按支出分类排列，同一分类内再按消费日期排列。

## 目标

- 资料包记录按分类配置顺序优先排列。
- 同一分类内按消费日期升序排列。
- 同一分类且同一天的记录按记录 ID 升序排列，保证结果稳定。
- 未分类记录排在所有已有分类之后。
- 汇总表、打印版 PDF、发票原件和支撑材料继续共用同一套序号和顺序。
- 两种资料包布局都采用相同记录顺序；不改变现有 ZIP 目录结构和附件类型顺序。

## 方案

在资料包统一编号入口 `invoice_sorting.exporter.naming.package_items()` 中调整排序键，不在各输出组件中分别排序。

排序键依次为：

1. 是否未分类：已分类在前，未分类在后；
2. 分类配置顺序 `Category.sort`；
3. 分类 ID，用于分类顺序相同时稳定排序；
4. 消费日期 `Expense.spent_on`；
5. 记录 ID。

`package_items()` 排序并生成序号后，现有汇总表、打印版 PDF、发票原件和支撑材料继续消费同一份 `PackageItem` 列表。因此不需要改变导出流程、文件命名或 ZIP 结构。

## 边界与兼容性

- 已归档分类仍按其保存的 `sort` 和 ID 排序，因为历史支出仍可引用该分类。
- 未分类记录之间按消费日期和记录 ID 排序。
- 附件在单条记录内仍按既有材料类型顺序和附件 ID 排序。
- “按支出分组”和“按材料类型分组”都使用新顺序，保证序号在所有输出中一致。

## 验证

采用 TDD 增加回归测试，先证明现有日期优先排序不满足以下规则，再实现最小改动：

- 分类配置顺序优先于日期；
- 同一分类内日期升序；
- 同日按记录 ID 稳定排序；
- 未分类记录置后；
- 原有附件类型排序和资料包导出测试继续通过。

完成后运行相关后端单元测试、资料包导出集成测试，以及与改动范围匹配的后端测试集。
